# Medaker (מדקר) — project context for Claude

Touch-first web app for practising **Biblical cantillation (טעמי המקרא)**: the learner
reads an unpointed verse in Torah-scroll (STAM) style and "stabs" (מדקר, like a Yad)
each word with the gesture that matches its hidden cantillation mark.

Read this file fully before touching code. It is the single source of truth for
decisions that are *not* derivable from the code itself. Update it when a decision
changes. Also read `AGENTS.md` (auto-generated by Next.js — this Next version differs
from training data; check `node_modules/next/dist/docs/` before using an API).

- The app is single-theme (navy). `html { color-scheme: dark }`; no light mode.

Motion: `animate-flash-correct` (gold→emerald glow ring), `animate-flash-incorrect`
(4px horizontal shake). Keep feedback ≤ 700 ms so it never delays the next gesture.

## 4. Domain model

```
Verse (pointed string) ──tokenizeVerse()──► WordToken[]
WordToken { pointed, display (STAM), marks: TaamDefinition[], primaryMark,
            requiredGesture (resolved IN VERSE CONTEXT), appliedRule: ContextRuleId | null }
```
`tokenizeVerse` is two-pass: (1) per-word marks + `primaryMark`; (2) `resolveGesture(tokens, i)`
for every word, because a word's gesture depends on the marks that follow it (§6b).
- **Token = touch target.** Whitespace-split; a maqaf group (`עַל־פְּנֵ֣י`) stays ONE token
  (one accentual unit). Stand-alone `׀` (paseq), `׃` (sof pasuq), `־` tokens attach to the
  previous word.
- **primaryMark / requiredGesture:** among the token's mapped marks, take the non-NONE mark
  with the lowest `rank` (0 emperors → 4 paseq; 9 = conjunctive/NONE). Ties → first in text
  order. Examples: `הָאָֽרֶץ׃` = meteg(NONE) + sof pasuq(LONG_PRESS) → LONG_PRESS;
  `וַֽיִּתְמַהְמָ֓הּ ׀` = meteg + shalshelet(rank 1) + paseq(rank 4) → ZIGZAG.
- A word requires **exactly one** gesture. Multi-gesture words are out of scope.
- `primaryMark` is chosen by rank from marks whose **default** gesture is not NONE; rules are
  then evaluated for that mark only.

## 5. Unicode handling rules (`src/lib/hebrew/unicode.ts`)

All input is `normalize("NFD")`-ed first. Ranges (Hebrew block U+0590–U+05FF):

| Class | Regex | Members |
|-------|-------|---------|
| Cantillation | `[֑-֯]` | all 31 accents incl. U+05AF masora circle |
| Points | `[ְ-ׇֽֿׁׂׅׄ]` | vowels, dagesh, **meteg (05BD)**, rafe, shin/sin dots, upper/lower dot, qamats qatan |
| Non-STAM punctuation | `[׀׃׆]` | paseq, sof pasuq, nun hafukha — removed from display, kept in data |
| Maqaf | `־` | rendered as a **space** in STAM display (no maqaf in a scroll, and the font has no glyph) |
| Format chars | `[͏‌-‏﻿]` | CGJ, ZW(N)J, LRM/RLM, BOM — always stripped |

`toStamDisplay()` = strip format chars → strip all marks → strip non-STAM punct →
maqaf→space → collapse whitespace. `extractCantillation()` / `marksOf()` read the data
layer. Never strip on the data layer; never validate on the display layer.

Zarqa encoding gotcha: real texts (WLC/Sefaria) encode the 21-books *zarqa* as **U+05AE
ZINOR** and use **U+0598 ZARQA** for *tsinnorit* (poetic books). The sheet follows that
practice (05AE → זרקא, 0598 → צינורית); both map to TILDE, so it is harmless either way.
Pashta (U+0599) may appear twice on one word — deduplicated.

## 6. Gesture vocabulary and mapping (`data/taamim-mapping.xlsx` → `taamim.generated.json`)

**Pipeline:** the sheet (columns `name | Unicode | example | defaultGesture | contextRule |
expectedGesture`) is imported with `npm run import:taamim` → `src/lib/taamim/taamim.generated.json`
(35 marks, 18 rules) → `config.ts` merges stable ids / English names / ranks (`TAAM_META`) →
`TAAMIM`. **Never hand-edit the generated JSON**; `import.test.ts` fails if it is stale.

Importer rules (`scripts/import-taamim.mjs`):
- A mark spanning several sheet rows = continuation rows with empty `name`/`Unicode` that add one
  more `(contextRule, expectedGesture)` pair. Rules keep sheet order.
- `Unicode` cells like `0591` arrive as the number 591 (Excel); digits are re-read as hex.
- Hebrew `contextRule` text → identifier via `CONTEXT_RULE_TEXT` (exact, whitespace-normalised).
  Unregistered text **throws** — new rules must be registered deliberately (§6b).
- Gesture labels: `none · long-press · diagonal · triple-tap · קשקוש · tilde · swipe-down · double swipe-down`.

| GestureType         | Hebrew label            | Default for |
|---------------------|-------------------------|-------------|
| `LONG_PRESS`        | לחיצה ארוכה (0.5 s)     | סגולתא 0592 · זקף קטון 0594 · זקף גדול 0595 · רביע 0597 · תביר 059B · גרש 059C · גרש מוקדם 059D · גרשיים 059E · קרני פרה 059F · תלישא גדולה 05A0 · פזר 05A1 · אתנח הפוך 05A2 · ירח בן יומו 05AA |
| `DIAGONAL`          | אלכסון יורד `\` (down & right) | טיפחא 0596 · יתיב 059A · דחי 05AD · פסק 05C0 |
| `TRIPLE_TAP`        | הקשה משולשת             | אתנחתא 0591 |
| `ZIGZAG`            | קשקוש כלפי מעלה         | שלשלת 0593 |
| `TILDE`             | גל ~ / ∞ מימין לשמאל    | צינורית 0598 · זרקא 05AE |
| `SWIPE_DOWN`        | החלקה למטה              | סוף פסוק 05C3 |
| `SWIPE_DOWN_TWICE`  | החלקה למטה, ושוב החלקה למטה (one finger, two sequential strokes) | — (only via the LAST_MAJOR_BEFORE_SOF_PASUK rule; the sheet calls it `double swipe-down`) |
| `NONE`              | ללא                     | פשטא 0599 · מונח 05A3 · מהפך 05A4 · מרכא 05A5 · מרכא כפולה 05A6 · דרגא 05A7 · קדמא 05A8 · תלישא קטנה 05A9 · עולה 05AB · עילוי 05AC · סימן עגול 05AF · מתג 05BD · מקף 05BE |

Changes vs. the first sheet (2026-09-16): גרש/גרש מוקדם moved from diagonal to long-press by
default; סוף פסוק moved from long-press to swipe-down; two new gesture types.

`RecognizedGesture = GestureType | "TAP" | "UNKNOWN"`. TAP (1–2 taps) and UNKNOWN are
**not attempts**: they never count as right or wrong (single tap is how users explore).

### 6b. Context rule engine (`src/lib/taamim/rules.ts`)

Some marks carry an ordered chain of `(contextRule → expectedGesture)` pairs. For the word at
index *i*: take `primaryMark`; walk its `rules` in sheet order; the **first rule whose evaluator
returns true** sets `requiredGesture = expectedGesture` and `appliedRule = id`; otherwise
`requiredGesture = defaultGesture`. Evaluators see `RuleContext { tokens, index, mark, sequence,
position }` where `sequence = markSequence(tokens)` is every mark of the verse in reading order
(each token's marks in text order — so a paseq attached to a word comes *after* that word's accent).

| Rule id | Sheet text (Hebrew) | Evaluates true when | Marks |
|---------|--------------------|---------------------|-------|
| `LAST_MAJOR_BEFORE_SOF_PASUK` | במקרה שהוא הטעם האחרון מסוג (triple-tap / long-press) עד לסוף הפסוק (swipe-down) | no later mark in the verse is *major* AND a sof pasuq (`SWIPE_DOWN` default) occurs later | אתנחתא, סגולתא, זקף קטון/גדול, תביר, גרש, גרש מוקדם, גרשיים, קרני פרה, תלישא גדולה, פזר, אתנח הפוך, ירח בן יומו → `SWIPE_DOWN_TWICE` |
| `NEXT_MAJOR_IS_REVIA_WITHOUT_PASEK` | במקרה שהטעם מסוג triple-tap / long-press הבא אחריו הוא רביע (597) ואין ביניהם פסק (05C0) | scanning forward, the first *major* mark is רביע U+0597 and no פסק U+05C0 was met before it | גרש, גרש מוקדם, גרשיים, קרני פרה, תלישא גדולה → `DIAGONAL` |

*Major* = a mark whose **default** gesture is `TRIPLE_TAP` or `LONG_PRESS` (`isMajorMark`), exactly
as the sheet words it. Rules are data-driven: רביע is major but has no rule row, so a verse-final
revia stays `LONG_PRESS`. Verses without a sof pasuq never trigger the first rule.

Examples (all in `rules.test.ts`): Gen 1:1 אלהים (etnahta, only a tipcha follows) →
`SWIPE_DOWN_TWICE`; Gen 1:2 תהום (etnahta, a zaqef follows) → `TRIPLE_TAP`; Gen 19:16 האנשים
(geresh … munah … revia) → `DIAGONAL`; `אָ֜ ׀ בְּ֗` (paseq between) → `LONG_PRESS`.

**Adding a conditional rule**
1. Add the row(s) to `data/taamim-mapping.xlsx` (continuation rows for extra rules on a mark).
2. Register the exact Hebrew text → new id in `CONTEXT_RULE_TEXT` (`scripts/import-taamim.mjs`).
3. Add the id to `ContextRuleId` and an entry `{ labelHe, describe, evaluate }` in `CONTEXT_RULES`
   (`rules.ts`). Evaluators must be pure functions of `RuleContext`.
4. `npm run import:taamim`; add cases to `rules.test.ts` (fires / does not fire / chain order).
5. If it introduces a new gesture: extend `GestureType`, `GESTURE_TYPES`, labels/icons, the
   recognizer (§7) and `GestureLegend`.

Validation entry points: `validateGestureInContext(tokens, index, received)` (live resolution —
what `TaamWord` uses) and `validateGesture(token, received)` (uses the tokenizer's precomputed
`requiredGesture`/`appliedRule`; identical result for tokenizer output).

## 7. Gesture recognition logic (`src/lib/gestures/*`)

Coordinates are **screen space** (+x right, +y down) even though the page is RTL.
"Right-to-left" always means decreasing x.

### 7.1 Pointer state machine (`useGestureRecognizer`)
One instance per word. `setPointerCapture` on down; element must have `.gesture-target`.

```
down ──┬── still for longPressMs(500) ─────────────► LONG_PRESS  (emitted from the timer, up is ignored)
       ├── up ≤ tapMaxMs(300) & moved ≤ tapSlopPx(10) ─► tap++  ; 3 taps with gaps ≤ tapGapMs(500) → TRIPLE_TAP
       │                                                  else after the gap window → TAP{taps}
       ├── moved > slop … up ─────────────────────────► classifyStroke(points)
       │        └── SWIPE_DOWN ──► held as pendingSwipe; finger lifted, then a 2nd SWIPE_DOWN starting within
       │                           swipeTwiceGapMs(600) → SWIPE_DOWN_TWICE; otherwise the lone SWIPE_DOWN is emitted
       │                           when the window closes (any other gesture flushes the pending swipe first).
       │                           Strictly ONE finger: a pointerdown while a stroke is active is ignored, so
       │                           multi-touch never forms a gesture — two fingers down = one SWIPE_DOWN at most.
       └── pointercancel ─────────────────────────────► reset, nothing emitted
```
A press released between 300–500 ms is ignored (neither tap nor press) to avoid noise.
Because of the swipe-twice window, feedback for a single swipe-down is delayed by ≤ 600 ms.

### 7.2 Stroke classifier (`classifyStroke`) — order matters
1. Path length < `minStrokePx`(24) → UNKNOWN.
2. **Upward zigzag heuristic** → ZIGZAG: net upward ≥ max(20px, 50 % of bbox height),
   bbox width ≥ 12px, and **≥ `zigzagMinChanges`(3) X-direction reversals** (8 px hysteresis).
3. **$1 recognizer** over `TEMPLATES` with bounded rotation ±20° (no indicative-angle
   normalisation — orientation is meaningful). Best score < `dollarOneMinScore`(0.7) → UNKNOWN.
4. Map template → candidate gesture, then **directional post-check**:
   - `backslash` → DIAGONAL only if chord angle ∈ [20°, 70°] below +x (top-left→bottom-right)
     and path/chord < 1.3 (straight). `/`, reversed `\`, horizontals, upward verticals are distractors.
   - `vline-down` → SWIPE_DOWN only if chord angle is within ±`swipeDownToleranceDeg`(20) of 90°
     (straight down) and path/chord < 1.3. 20°–70° is DIAGONAL, 70°–110° is SWIPE_DOWN: no overlap.
   - `tilde-rtl-*` / `infinity-rtl-*` → TILDE only if right-to-left:
     *tilde*: ends ≥ 40 % of width left of start, ≥ 1 vertical reversal, ≤ 1 horizontal reversal;
     *infinity*: near-closed (end within 50 % of the long side), first quarter heads left,
     ≥ 1 horizontal and ≥ 2 vertical reversals, width ≥ 0.8 × height.
   - Anything else (incl. `tilde-ltr`, `infinity-ltr`, `circle`, `check-mark`, `zigzag-down`) → UNKNOWN.

Distractor templates are load-bearing: without them $1 always returns *something*.

### 7.2b Tuning thresholds (`GESTURE_CONFIG` → `config-store.ts` → Tuning panel)
- `GESTURE_CONFIG` (taamim/config.ts) = compiled defaults. Every key is a number.
- `getGestureConfig()` (gestures/config-store.ts) = defaults ⊕ localStorage overrides
  (`medaker.gestureConfig.v1`) ⊕ URL query overrides (`?longPressMs=400&dollarOneMinScore=0.65`).
  `classifyStroke()` and the hook read it at event time, so changes apply instantly.
- **On-device tuning:** open `?tune=1` (or the footer link "כיוונון מחוות"). Sliders edit the
  store live; the readout shows the last gesture (type, duration, path length, template,
  $1 score, reject reason). "העתק JSON" copies the full config — paste proven values back
  into `GESTURE_CONFIG` and keep `classify.test.ts` green. "איפוס" clears overrides.
- Adding a key: add it to `GESTURE_CONFIG` **and** to `GESTURE_CONFIG_META` (label/min/max/step).

### 7.3 Browser-side requirements
- `.gesture-target { touch-action: none; user-select: none; -webkit-touch-callout: none }`.
  `none` ⊇ `manipulation`: it also blocks scrolling on the element, which is required for
  `pointermove` to keep firing during strokes. Scroll the page from the margins/background.
- `pointerdown` → `preventDefault()` (kills text selection & compat mouse events);
  `contextmenu` → `preventDefault()` (Android long-press menu).
- `viewport.userScalable=false, maximumScale=1, viewportFit=cover` as belt-and-braces against
  double-tap / pinch zoom; `overscroll-behavior: none` on html+body kills pull-to-refresh and
  rubber-banding so a swipe-down never reloads the page. `appleWebApp.capable` lets the app run
  without Safari chrome when added to the home screen (fewer edge-swipe conflicts).

## 8. Application modes (`Trainer.tsx`)

| | Practice (תרגול) | Exam (מבחן) |
|-|------------------|-------------|
| Text | STAM; hint toggle swaps to pointed text (`font-pointed`) | STAM only, no hint |
| Target | one highlighted word (gold underline); NONE-words auto-complete | any word accepts gestures |
| Feedback | immediate green/red flash + toast | none; word gets a navy underline when answered |
| Progress | advances on correct; auto-advances to next verse when all required words are done | "סיים מבחן" → `scoreExam()` |
| Score | mistakes counter | accuracy = correct / (required + falsePositives) |

`TaamWord` statuses: `idle | target | done | answered | locked`. `feedback: "immediate" | "silent"`.
`acceptAnyWord` lets exam mode take gestures on non-target words.

## 9. Data
`src/data/verses.json` holds 5 sample verses (Gen 1:1-3, 1:7 for zarqa/segolta, 19:16 for
shalshelet + paseq). **Verified 2026-09-16** character-for-character against two witnesses:
Sefaria API v3 version "Tanach with Ta'amei Hamikra" (WLC) and tanach.us UXLC 2.5.
- `npm run verify:verses` re-checks against Sefaria (add `--uxlc` for the second witness,
  `--write` to refresh `verses.wlc.json`). Run it whenever verses are added or edited.
- `verses.test.ts` compares `verses.json` to the snapshot offline, so CI needs no network.
- Comparison normalisation: strip U+034F CGJ, drop whitespace after maqaf, NFD.
  (UXLC inserts CGJ + meteg-before-vowel in leading-meteg words; WLC/Sefaria do not.)
- Sefaria's default Hebrew version "Miqra according to the Masorah" follows the Aleppo
  tradition (e.g. וַיַּחֲזִ֨יקוּ, יְהֹוָ֖ה, doubled segolta) — do **not** mix it with WLC text.

`next.config.ts`, `images.unoptimized`, `trailingSlash`). `npm run build` writes `out/`.

**Base path.** A project site lives at `https://<user>.github.io/<repo>/`, so the build must know
the sub-path: `NEXT_PUBLIC_BASE_PATH=/<repo>`. Next prefixes routes, chunks and `next/font` files
by itself; **`next/image` src and metadata icon URLs are not prefixed** — always go through
`withBasePath()` (`src/lib/basePath.ts`) for `/public` assets. Unset locally → root paths.
`public/.nojekyll` stops GitHub from dropping the `_next/` folder.

**Workflow** (`.github/workflows/deploy.yml`, on push to `main` or manual dispatch):
`npm ci` → lint → typecheck → test → resolve basePath from the repo name (empty for
`<user>.github.io`) → `npm run build` → `upload-pages-artifact` (`out/`) → `deploy-pages`.
It needs `permissions: pages: write, id-token: write` and the repo setting
**Settings → Pages → Source: GitHub Actions** (one-time, manual).

**First-time setup**
1. Create the repo (any name; `medaker` assumed by `build:pages`/`preview:pages`), push `main`.
2. Settings → Pages → Build and deployment → Source: *GitHub Actions*.
3. Push (or run the workflow manually). The deploy job prints the URL.

**Verify an export locally, exactly as Pages serves it**
```bash
npm run build:pages      # NEXT_PUBLIC_BASE_PATH=/medaker next build
npm run preview:pages    # http://localhost:3101/medaker/  (404s outside the base path, like Pages)
```
Then open it on a phone on the same Wi-Fi (`http://<mac-ip>:3101/medaker/`) — or use the
deployed URL. Add `?tune=1` for the gesture readout while testing.

**Gotchas**
- `basePath` is inlined at build time; changing the repo name means rebuilding.
- The tuning overrides live in `localStorage`, which is per-origin: production and local previews
  do not share them.
- No server features may be added (route handlers, dynamic params without generateStaticParams,
  middleware) — see Next "static exports → unsupported features".
